# Level Designer — руководство

Как пользоваться конструктором уровней лабиринта: что откуда берётся, где что настраивать и как добавлять новый визуал.

---

## 1. Быстрый старт (5 минут)

1. **Maze → Dev → Create Placeholder Theme**. Создаётся тестовая тема с простыми префабами. Нужно один раз; если у вас уже есть своя тема, этот шаг пропустите.
   Для запуска уровня в игре нужен ещё игрок: **Maze → Dev → Create Placeholder Player** (тоже один раз, см. раздел 9).
2. **Maze → Level Designer**. Открывается окно конструктора.
3. Кнопка **New Level** на верхней панели: сохраните ассет уровня, например в `Assets/_Project/Data/Levels/`.
4. Вкладка **Visuals** → в поле **Theme** укажите тему (например, `PlaceholderTheme`).
5. Вкладка **Generation** → задайте размер (**нечётный**, например 21×21) и нажмите **Generate New**.
6. Вкладка **Edit**: дорисуйте стены и двери, расставьте ключи, зомби, оружие и прочее.
7. Вкладка **Validate**: ошибок быть не должно.
8. **Build Preview** — посмотреть уровень в 3D в сцене. **Build / Sync** — зафиксировать уровень для игры.
9. **Play** или **Test from Start ▾** — сразу сыграть уровень (Build / Sync делается сам).

## 2. Главные идеи (прочитать обязательно)

**Логика и визуал — разные слои.**
- Тип клетки (`Wall` / `Floor` / `Door`) определяет геймплей: можно ли пройти, видно ли сквозь неё, летит ли пуля.
- Префаб (`wall_02.prefab`) отвечает только за внешний вид. Никакой игровой логики в префабе нет.

**Случайность есть только при создании уровня.**
- Генератор и подбор визуала используют seed'ы.
- Результат (какая клетка какой вариант получила) **сохраняется в уровень**.
- Игра никогда не выбирает префаб случайно: один и тот же уровень всегда выглядит одинаково на любом устройстве.

**Два независимых seed'а:**

| Seed | Что определяет |
|---|---|
| **Maze Seed** | форму лабиринта, стартовые точки и выходы |
| **Visual Seed** | первоначальный выбор визуальных вариантов (какой пол, какая стена) |

Если поменять только Visual Seed, лабиринт останется тем же, изменится только внешний вид. И то лишь после нажатия **Regenerate Visuals**: просто изменение числа уровень не трогает.

**Генератор даёт черновик, дизайнер доводит до финала.** После **Generate New** можно менять что угодно. Генератор сам ничего не перегенерирует.

**Пол есть под каждой клеткой.** Визуально у клетки два слоя:
- **Floor** — у **всех** клеток: пол, стена, дверь. Поэтому пол сплошной и вокруг тонких стен нет пустот;
- **Wall** — только у клеток-стен, ставится поверх пола.

Это чисто визуальное правило. Для геймплея стена остаётся стеной.

**Приоритет визуала клетки или объекта:**
```
Ручной Override дизайнера  >  Сохранённое назначение  >  Default-вариант набора  >  нет визуала (ошибка)
```

## 3. Где что лежит

| Что | Где |
|---|---|
| Уровни (`LevelData`) | `Assets/_Project/Data/Levels/` |
| Визуальные темы и наборы | `Assets/_Project/Data/Themes/` |
| Тестовые префабы-заглушки | `Assets/_Project/Art/Placeholders/` |
| Игрок: параметры (`PlayerDefinition`) и внешний вид (`PlayerVisual`) | `Assets/_Project/Data/Player/` |
| Код логики уровня (данные, генератор, визуал, валидатор) | `Assets/_Project/Scripts/Core/` |
| Код конструктора (окно, инструменты) | `Assets/_Project/Scripts/Editor/LevelDesigner/` |
| Тесты | `Assets/_Project/Tests/EditMode/` |

**Как связаны ассеты:**
```
LevelData (уровень)
├── Generation settings     — размер, seed'ы, плотность петель
├── Geometry                — тип каждой клетки
├── Объекты                 — двери, ключи, старты, выходы, зомби, оружие, аптечки, фрагменты карты, патрули
├── VisualTheme ──────────► VisualTheme (тема, общая для многих уровней)
│                             ├── Floor Set ─► VisualSet ─► варианты: id, prefab, weight, category, color tag
│                             ├── Wall Set
│                             ├── Door Set, Key Set, Exit Set, Medkit Set, Weapon Set, Zombie Set, MapFragment Set
└── VisualData              — сохранённый результат: (клетка, слой Floor/Wall) или объект → VariantId + поворот,
                              плюс ручные overrides
```

## 4. Окно конструктора

**Слева** — вкладки и инспектор выделенного. **Справа** — схема уровня (вид сверху, север вверху).

### Управление на сетке
| Действие | Как |
|---|---|
| Масштаб | колесо мыши |
| Сдвиг схемы | кнопка **Hand (H)** на верхней панели (или клавиша **H**), затем тянуть ЛКМ. **Зажатый пробел** включает руку временно. Также работают средняя кнопка мыши и **Alt + ЛКМ**. Текущий инструмент при этом не сбрасывается |
| Применить инструмент или выбрать | **ЛКМ** (можно протягивать) |
| Удалить последнюю точку патруля | **ПКМ** (инструмент Patrol) |
| Удалить выделенный объект | **Delete** |
| Вернуться к инструменту Select (и выключить руку) | **Esc** |
| Отменить или повторить | **Ctrl+Z / Ctrl+Y**. Один мазок кистью = один шаг отмены |
| Вписать уровень в окно | кнопка **Fit** |

### Обозначения на схеме
| Значок | Что это |
|---|---|
| тёмная клетка / светлая / коричневая | стена / пол / дверь |
| **S** | стартовая точка игрока |
| **E** | выход |
| **D** | дверь. Цвет буквы — цвет пары ключ↔дверь, белая — дверь без ключа |
| **K** | ключ (в цвете своей двери) |
| **Z** | зомби. Красная линия — его маршрут патруля |
| **W** | оружие |
| **+** | аптечка |
| **M** | фрагмент карты. Фиолетовая рамка — область, которую он открывает. В игре фрагмент подбирается при входе в клетку и открывает на карте свою область: стены, проходы, двери, выходы и старты. Все фрагменты уровня собраны — третья звезда (уровень без фрагментов даёт её сразу) |
| красная / оранжевая рамка | ошибка / предупреждение валидатора в этой клетке |
| жёлтая рамка | выбранная клетка |
| голубая рамка | выбранный объект |

**Строка внизу** показывает клетку под курсором, её визуал (пол + стена: вариант, поворот, источник) и итог валидации.

**Инспектор выделенного (слева внизу):**
- информация о клетке и её визуал по слоям с возможностью ручной замены:
  - **Floor override** — пол, у любой клетки, в том числе под стеной;
  - **Wall override** — стена, только у клеток-стен;
- кнопки объектов в клетке;
- настройки выбранного объекта.

## 5. Вкладка Generation

| Поле | Смысл |
|---|---|
| Width / Height | размер в клетках (1 клетка = 1×1 м). **Только нечётные** (21, 25, 31…), минимум 5×5. Рамка из стен плюс чередование «проход / стена» по одной клетке ровно укладываются в нечётный размер |
| Maze Seed / Visual Seed | см. раздел 2. Кнопка **Random** подставляет случайное число |
| Algorithm | алгоритм лабиринта (сейчас Randomized DFS / Recursive Backtracker) |
| Loop Density | 0 = лабиринт без петель (между любыми точками один путь), 1 = снесены все внутренние стены между комнатами |
| Player Starts / Exits | сколько стартов и выходов поставить автоматически |

**Generate New — разрушительная операция.** Она заменяет геометрию, удаляет все объекты и весь визуал, включая ручные overrides. Перед запуском окно спросит подтверждение, а отменить её можно через Ctrl+Z.

**Как генератор расставляет старты и выходы.** Он ставит их в тупики, разнося как можно дальше друг от друга по длине пути. Выход получается максимально далеко от старта.

**Нечётный размер нужен только генератору.** После генерации уровень можно редактировать как угодно, валидатор размер не проверяет.

**Сверху и справа стена в две клетки?** Значит, уровень сгенерирован с чётным размером по старому правилу. Поставьте нечётный размер и нажмите Generate New, либо уберите лишние стены кистью.

## 6. Вкладка Edit — инструменты

| Инструмент | Что делает |
|---|---|
| **Select** | Клик выбирает клетку и объект (повторный клик перебирает объекты в клетке). Перетаскивание двигает объект |
| **Wall / Floor** | Кисть: клик или протягивание. Пол поверх двери удаляет дверь |
| **Door** | Делает клетку дверью и создаёт объект двери |
| **Start / Exit / Medkit** | Ставит объект на клетку пола |
| **Key** | Ставит ключ. Чтобы ключ сразу привязался к двери, используйте кнопку в инспекторе двери (см. ниже) |
| **Zombie** | Ставит зомби. В опциях инструмента выберите **Zombie Definition** и **Facing** (куда смотрит) |
| **Weapon** | Ставит оружие. В опциях выберите **Weapon Definition** |
| **Fragment** | Ставит фрагмент карты и сразу переключает на **Region** |
| **Region** | Протяните прямоугольник: это область карты, которую откроет выбранный фрагмент |
| **Patrol** | Выберите зомби, затем кликайте по клеткам: точки маршрута A→B→C→…→A. ПКМ удаляет последнюю |
| **Erase** | Удаляет объекты в клетке. Дверь при удалении превращается в пол |

**Правила расстановки** (тулза не даст их нарушить):
- объекты ставятся только на пол;
- в одной клетке — один объект;
- исключение — зомби: их может быть несколько в клетке, и они могут стоять на предметах;
- зомби не может стоять на стартовой точке.

### Двери и ключи — строгое правило
- **Один ключ открывает ровно одну дверь** и после использования исчезает из инвентаря.
- Ключ только отпирает дверь. Открывает и закрывает её игрок отдельным действием, сколько угодно раз.
- **Ключ всегда того же цвета, что и его дверь.** Цвет подбирается автоматически:
  - запертая дверь получает цветной вариант;
  - разные пары по возможности получают разные цвета;
  - ключ берёт цвет своей двери;
  - дверь без ключа — нецветная.

Как связать ключ с дверью:
1. Выберите дверь (Select).
2. В инспекторе:
   - **Key** — выбрать существующий ключ. Если он был привязан к другой двери, он оттуда отвяжется;
   - или **Place a new key for this door** — следующий поставленный ключ сразу привяжется.
3. **Initially Open** — дверь в начале уровня открыта.

Если вручную поменять визуал двери (Override) на другой цвет, ключ перекрасится автоматически.

### Инспектор объекта
- **Id** — можно переименовать. Ссылки (дверь→ключ, зомби→патруль) и визуал обновляются автоматически.
- **Override** — ручной выбор визуального варианта и поворота.
- **Delete** — удалить объект.

## 7. Вкладка Visuals

- **Theme** — визуальная тема уровня.
- **Visual Sets** — какие наборы входят в тему, только просмотр. Редактировать наборы — в Inspector самих ассетов.
- **Visual Seed** + **Regenerate Visuals** — заново раздать варианты по весам.
  - Геометрия, объекты, двери, ключи и зомби **не меняются**.
  - Ручные overrides **сохраняются**, если не включить **Also clear manual overrides**.
- **Manual Overrides** — список ручных замен: клик по координате выделяет клетку, кнопка **Clear** удаляет замену.
- **Visual Distribution** — фактическое распределение вариантов против весов. Проценты считаются внутри категории. Небольшое расхождение нормально: клеток конечное число. Статистика пола включает пол под стенами.

**Ручная замена визуала клетки:** выберите клетку → в инспекторе **Floor override** или **Wall override** → выберите вариант. Пункт **(automatic)** убирает замену.

- Замена **пола** сохраняется при любой перерисовке клетки: пол есть всегда.
- Замена **стены** удаляется, когда клетка перестаёт быть стеной.

## 8. Вкладка Validate

Валидатор запускается **автоматически после каждого изменения**. Кнопка **Show** у проблемы выделяет её клетку на схеме.

| Уровень | Значение |
|---|---|
| **Error** | Уровень не готов. Надо исправить |
| **Warning** | Возможная проблема (недостижимое оружие, ненужный ключ, повтор цвета) |
| **Info** | Справка (например, длина кратчайшего пути от старта до выхода) |

**Частые ошибки:**

| Код | Что значит | Что делать |
|---|---|---|
| `InsideWall` | объект стоит в стене | передвинуть объект или нарисовать пол |
| `DoorCellWithoutDoor` | клетка-дверь без объекта двери | перерисовать кистью Door или Floor |
| `MissingKeyReference` | дверь ссылается на несуществующий ключ | выбрать ключ в инспекторе двери |
| `KeySharedByDoors` | один ключ у нескольких дверей | у каждой двери свой ключ |
| `KeyDoorColorMismatch` | цвет ключа ≠ цвет двери, или запертая дверь без цвета | убрать ручной Override или Regenerate Visuals |
| `NoReachableExit` / `ExitUnreachable` | из старта не дойти до выхода (с учётом ключей) | проверить стены, двери и расположение ключей |
| `Intersection` | несколько объектов в одной клетке | развести объекты |
| `FragmentOverlap` / `InvalidFragmentRegion` | области фрагментов пересекаются или выходят за уровень | перерисовать Region |
| `MissingVisual` / `UnknownVariant` | у клетки или объекта нет визуала, или вариант удалён из набора | Regenerate Visuals или поправить Override |
| `WallCategoryWithoutVariants` | в наборе стен нет вариантов нужной формы (угол, Т и т.д.) | добавить вариант этой категории (раздел 10) |
| `StaleWallVisual` | форма стены изменилась, визуал устарел | Regenerate Visuals |
| `OverrideLayerMismatch` | ручная замена стены стоит на клетке, которая уже не стена (замена игнорируется) | убрать замену в Visuals → Manual Overrides |
| `BrokenPrefabReference` | у варианта нет префаба или он удалён из проекта | назначить префаб в наборе |
| `GeometryMeshNotReadable` | меш пола или стены без Read/Write — в игре его не будет | включить Read/Write в импорте модели |
| `GeometryShaderUnsupported` | материал пола или стены не на шейдере Maze/Geometry — туман войны не скроет эти клетки | переключить материал на Maze/Geometry |
| `NoVisualTheme` / `MissingVisualSet` | нет темы или нужного набора | назначить тему, заполнить набор |

## 9. Build Preview и Build / Sync

- **Build Preview** — строит уровень из настоящих префабов в открытой сцене, в объекте `[Maze Level Preview]`. Это только просмотр: объект не сохраняется со сценой. **Clear Preview** убирает его.
  - Превью — снимок на момент нажатия. Сам уровень после правок кистью обновляется сразу, в том числе его визуал. Чтобы увидеть изменения в сцене, нажмите **Build Preview** ещё раз: старое превью заменится новым. Ничего перегенерировать не нужно.
- **Build / Sync** — фиксирует уровень для игры:
  1. запускает валидацию (при ошибках спросит, продолжать ли);
  2. делает уровень Addressable с адресом `Levels/<имя уровня>` в группе **Maze Levels**;
  3. делает Addressable все префабы темы, которых ещё нет в Addressables, в группе **Maze Visuals**;
  4. добавляет уровень в **каталог уровней** `Data/Levels/LevelCatalog.asset` (если каталога нет, создаёт его) или обновляет в нём адрес и название уровня;
  5. делает Addressable общие для всех уровней ассеты игрока (`PlayerDefinition`, `PlayerVisual` и его префаб) в группе **Maze Shared**. Если их нет, в консоли будет предупреждение: без игрока уровень в игре не запустится;
  6. сохраняет ассеты.

  **Никакой новой рандомизации Build / Sync не делает.**

- **Play / Test from Start** (справа на верхней панели):
  - **Play** — проверяет уровень, делает Build / Sync, входит в Play Mode со сцены Bootstrap (какие бы сцены ни были открыты) и сразу запускает этот уровень, минуя меню; старт случайный, как в игре;
  - **Test from Start ▾** — то же, но со стартовой точки, выбранной в списке (`Start #0`, `#1`, … — порядок, в котором старты лежат в уровне). Та же кнопка **Test from Start #N** есть в инспекторе выбранного старта;
  - уровень с ошибками валидации не запускается — сначала вкладка Validate;
  - «Play again» повторяет уровень с того же старта, «Main menu» ведёт в обычное меню. После остановки Play обычная кнопка Play Unity снова запускает открытые сцены.
- **Каталог уровней** — список уровней в главном меню игры. Уровень появляется в меню только после Build / Sync. В меню показывается **Display Name** уровня: поле *Settings → Display Name* в инспекторе ассета уровня. После его изменения сделайте Build / Sync ещё раз. Порядок уровней и удаление лишних — в инспекторе `LevelCatalog.asset`.
- Если игра не может загрузить уровень (например, в нём есть ошибки валидации), она показывает экран ошибки с причиной и возвращает в меню. Уровень с ошибками в игру не попадёт, даже если Sync сделан через «Sync Anyway».
- **Игрок** один на все уровни: `Data/Player/PlayerDefinition` (скорость, размер «тела» для столкновений со стенами, сила помощи на поворотах, HP) и `Data/Player/PlayerVisual` (префаб). Префаб игрока: pivot у ног, смотрит на +Z, без коллайдеров. Если в нём есть Animator с float-параметром **Speed**, игра передаёт туда скорость 0..1. При нескольких стартовых точках игра выбирает случайную при каждом запуске уровня.
- **Управление в игре:** WASD или стрелки — движение; Esc — пауза; E — действие (подобрать оружие, отпереть / открыть / закрыть дверь); 1 / 2 — ближнее / дальнее оружие; M или Tab — карта (закрыть — снова M, Esc или «Close»); ЛКМ или пробел — атака в сторону взгляда (удержание повторяет удар и автоматический огонь). На телефоне — экранный стик слева и кнопки справа: **Use** = действие (подобрать оружие, дверь), Melee / Ranged — переключить оружие, Attack — атака; карта и пауза — кнопки вверху. Встав на оружие, игрок видит подсказку «press Use (E) to pick up». Игра только в альбомной ориентации.
- **Как предметы ведут себя в игре** (учитывайте при расстановке):
  - **ключ** подбирается сам, когда игрок входит в клетку;
  - **запертая дверь**: E рядом с ней при нужном ключе только отпирает её (ключ тратится), открывает следующее нажатие E. Без ключа игрок видит сообщение, какой ключ нужен. Дверь без ключа открывается и закрывается по E. Закрыть дверь нельзя, если в проёме стоит игрок или зомби;
  - **аптечка** срабатывает при входе в клетку, только если HP не полный: лечит до полного и исчезает. При полном HP остаётся лежать;
  - **оружие** подбирается по E, когда игрок стоит в его клетке, и сразу становится активным. Если слот (ближнее / дальнее) уже занят, старое оружие выпадает в эту клетку. В начале уровня у игрока оружия нет;
  - закрытая дверь загораживает обзор — за ней ничего не видно.
- **Зомби в игре** (параметры — в ассете ZombieDefinition, поле **Detection Type**):
  - **Vision Only** — видит игрока в секторе **Vision Angle** перед собой на расстоянии **Vision Range**; стены и закрытые двери загораживают;
  - **Hearing Only** — реагирует на звуки (шаги, выстрелы, удары, двери, подбор) в пределах **Hearing Radius**, но не дальше, чем слышен сам звук (громкость задана у оружия и у игрока);
  - **Vision And Hearing** — замечает игрока в радиусе **Detection Radius**, стены не мешают;
  - заметив, идёт к месту, где видел/слышал игрока; потеряв — возвращается к ближайшей точке своего патруля и патрулирует дальше (без патруля — на свою клетку, смотрит в исходную сторону);
  - если игрок в соседней клетке (по стороне), бьёт: **Damage** раз в **Attack Interval** секунд; **Move Speed** — клеток в секунду, **Max Hp** — здоровье;
  - двери не открывают: закрытая дверь — стена для них; в клетку игрока не заходят, друг через друга проходят;
  - урон от игрока, который зомби не заметил, не заставляет его реагировать;
  - заглушки трёх типов: **Maze → Dev → Create Placeholder Zombies** (`Data/Zombies`).
- **Смерть игрока** (HP 0) — уровень проигран, на экране «Play again» и «Main menu».
- **Дев-уровень `Level_Items`** — копия Level_Dev с дверями, ключом, аптечкой, оружием, тремя зомби рядом со стартом и двумя фрагментами карты (левая и правая половины уровня), чтобы быстро проверить предметы. Это не игровой контент: его можно удалить (и из `LevelCatalog`).

## 10. Как добавить новый визуал (префаб)

### Требования к префабу
- **Размер:** одна клетка = **1×1 метр**. Центр клетки — это pivot префаба (0, 0, 0), пол на высоте Y = 0.
- **Без коллайдеров и Rigidbody.** Физика в проекте не используется.
- **Префаб стены — без пола.** Пол под стеной ставится отдельно, из набора пола. Если встроить пол в стену, два пола наложатся и будут мерцать (z-fighting). Низ стены — на Y = 0.
- **Префаб пола занимает всю клетку 1×1**, верхняя грань на Y = 0.
- **Никакой игровой логики в префабе.** Проходимость и прочее задаёт тип клетки.
- **Пол и стены — особые требования.** В игре их меши склеиваются в крупные куски (чанки 8×8 клеток), а туман войны прячет отдельные клетки прямо в шейдере. Поэтому для префабов **пола и стен**:
  - все материалы — на шейдере **Maze/Geometry** (как Standard: цвет, текстура, карта нормалей, metallic/smoothness, emission). Материал на другом шейдере покажется, но туман войны не сможет скрыть его клетки (`GeometryShaderUnsupported`);
  - у импортированных моделей включён **Read/Write** (Model → Read/Write в настройках импорта), иначе меш не попадёт в игру (`GeometryMeshNotReadable`). Встроенные примитивы Unity подходят как есть;
  - только MeshFilter + MeshRenderer. Свет, частицы, анимированные (skinned) меши в префабе пола или стены игра пропустит (`GeometryUnsupportedRenderer`). Если нужны — это отдельный объект, не геометрия клетки.
  - Двери, выходы, предметы и зомби — обычные префабы, для них ограничений нет.
- **Ориентация.** Префаб делается в «канонической» ориентации. Тулза сама повернёт его на 0/90/180/270° по соседям:

| Категория стены | Префаб соединяется с соседями | Пример |
|---|---|---|
| `Isolated` | ни с кем (одиночная колонна) | `wall_isolated` |
| `End` | только **север** (+Z) | тупиковый конец стены |
| `Straight` | **север + юг** | прямая стена вдоль оси Z |
| `Corner` | **север + восток** (+Z и +X) | угол |
| `TJunction` | **север + восток + юг** | Т-образное соединение |
| `Cross` | все четыре стороны | крест |
| `Special` | — | **никогда не ставится автоматически**, только вручную через Override |

- **Дверь** при повороте 0 перекрывает проход **север–юг**: полотно двери вытянуто вдоль оси X.
  - Чтобы дверь показывала состояния, добавьте на корень префаба компонент **Door Visual** и укажите в нём дочерние объекты: **Closed** (видна, пока дверь закрыта), **Open** (пока открыта, например полотно, прижатое к стене), **Locked** (пока заперта, например замок). Любое поле можно оставить пустым. Вместо объектов (или вместе с ними) можно указать **Animator** с bool-параметрами `Open` и `Locked`.
  - Без компонента Door Visual открытая дверь просто исчезает (прячутся её рендереры).
  - Не выключайте и не включайте сам корень префаба из своих скриптов — им управляет туман войны.
- **Выход** при повороте 0 «смотрит» на север. Тулза развернёт его к открытой стороне.
- **Остальные предметы** (ключ, аптечка, оружие, зомби, фрагмент) не поворачиваются автоматически.

Для образца откройте префабы в `Assets/_Project/Art/Placeholders/`.

### Шаги
1. Положите префаб в проект, например в `Assets/_Project/Art/...`.
2. Откройте нужный **VisualSet** в `Assets/_Project/Data/Themes/` (например, `PlaceholderWallSet`).
3. В списке **Variants** добавьте элемент и заполните:

| Поле | Что указать |
|---|---|
| **Id** | уникальное имя варианта (`wall_straight_03`). Это имя сохраняется в уровнях, **не переименовывайте его после использования** |
| **Prefab** | ваш префаб |
| **Weight** | вес при автоматическом выборе (подробнее ниже). **0** = только вручную |
| **Category** | для стен — форма (раздел выше); для остального — `General` |
| **Definition** | необязательно: вариант только для конкретного `WeaponDefinition` / `ZombieDefinition`. Например, модель дробовика только для дробовика |
| **Color Tag** | только для дверей и ключей: `red`, `blue`, `green`, `yellow`… Должен **совпадать** у двери и ключа одной пары. У нецветной двери поле пустое |

4. **Default Variant Id** набора — запасной вариант, если для формы стены нет ни одного варианта. Лучше указать; без него будет ошибка.
5. Чтобы новый вариант появился на **уже сделанных** уровнях, есть два способа:
   - **Regenerate Visuals** — перераздаёт все варианты по весам, ручные замены сохраняются;
   - или поставьте вариант точечно через **Override** в инспекторе клетки или объекта.

   На уже готовых уровнях **ничего не меняется само**: так задумано.
6. **Build / Sync** — новый префаб станет Addressable.

### Как работают веса
Вес — это относительная вероятность **внутри одной категории**. Пол под стенами выбирается по тем же весам, что и обычный пол. Пример для набора пола:
```
floor_01  Weight 80   →  ~80% клеток пола
floor_02  Weight 10   →  ~10%
floor_03  Weight 10   →  ~10%
floor_blood Weight 0  →  только вручную
```
- Для стен веса сравниваются только между вариантами одной формы: два `Straight` с весами 80/20 делят прямые стены 80/20.
- Сумма весов не обязана быть 100.
- Веса используются **только** при Generate New и Regenerate Visuals. В игре они не участвуют.

### Новая тема
1. **Create → Maze → Visual → Visual Theme**.
2. Для каждого вида создайте набор: **Create → Maze → Visual → Visual Set**. Поле **Kind** набора должно совпадать со слотом темы: Floor, Wall, Door, Key, Exit, Medkit, Weapon, Zombie, MapFragment.
3. Назначьте наборы в слоты темы.
4. Необязательно: поле **Fog Material** — материал тумана войны (шейдер `Maze/Fog`). Пусто — тумана нет, скрытые клетки просто не рисуются.
5. В уровне: вкладка **Visuals** → **Theme** → **Regenerate Visuals**.

### Туман войны
Скрытые клетки затянуты анимированной дымкой. Её вид задаёт материал `Assets/_Project/Art/Fog/Fog.mat` (назначен в `PlaceholderTheme`, пересоздать — **Maze → Dev → Create Placeholder Fog**; уже настроенный материал при этом не перезаписывается). Параметры материала, их можно менять прямо во время Play:

| Параметр | Что делает |
|---|---|
| Noise | бесшовная текстура шума (серая, канал R) |
| Fog Color / Wisp Color | цвет дымки и светлых прядей |
| Density | плотность (1 — за туманом ничего не видно) |
| Wisp Strength | насколько заметны пряди |
| Noise Scale | размер «облаков» для двух слоёв (меньше — крупнее) |
| Flow Layer 1 / 2 | скорость и направление дрейфа слоёв, клеток в секунду |
| Edge Blur Radius | ширина размытия края, клетки (больше — расплывчатее граница) |
| Edge Softness / Edge Offset | мягкость края и его сдвиг: «+» — в сторону скрытых клеток, «−» — заходит на видимые |
| Fade Time | за сколько секунд туман рассеивается или сгущается при смене видимости |
| Plane Height | высота плоскости тумана над полом |

Туман рисуется поверх всего (без проверки глубины): мягкий край затягивает и стены на границе видимой зоны, поэтому граница не обрезана. Клетки, уходящие из видимости, исчезают только когда туман их полностью затянул.

Туман — только картинка: видимость объектов, AI и Level Designer от него не зависят.

### Новое оружие или тип зомби
- **Create → Maze → Definitions → Weapon** / **Zombie** — игровые параметры (урон, магазин, радиус обнаружения и т.д.). Поле **Slot** у оружия — Melee (ближнее) или Ranged (дальнее).
- Параметры оружия:
  - общие: **Damage** (урон), **Sound Radius** (на сколько клеток удар/выстрел слышат зомби);
  - ближнее: **Attack Speed** (ударов в секунду), **Melee Range** (дальность до края цели, клетки), **Melee Arc** (ширина сектора перед игроком, градусы) — удар задевает всех в секторе, но не через стену или закрытую дверь;
  - дальнее: **Fire Interval** (секунд между выстрелами), **Magazine Size**, **Reload Time** (перезарядка автоматическая, когда магазин пуст; патроны бесконечны), **Fire Mode** (Single — выстрел на нажатие, Automatic — пока кнопка зажата), **Projectile Speed** (клеток в секунду). Пуля пролетает открытые двери и останавливается о стену, закрытую дверь или цель.
- Вид пули, вспышки попадания и взмаха ближнего боя общий для всех уровней: `Data/Combat/CombatVisual` (префабы смотрят вдоль +Z, без коллайдеров). Заглушки — **Maze → Dev → Create Placeholder Combat Visuals**.
- Для проверок есть заглушки: **Maze → Dev → Create Placeholder Weapons** создаёт в `Data/Weapons` нож и биту (ближнее) и пистолет (дальнее). Существующие ассеты не перезаписываются.
- Визуал задаётся отдельно, вариантами в Weapon Set / Zombie Set. Чтобы модель была только у этого оружия или зомби, укажите поле **Definition** у варианта.

## 11. Частые вопросы

**Поменял Visual Seed — ничего не изменилось.**
Так и задумано. Нажмите **Regenerate Visuals**.

**Нажал Regenerate Visuals — пропали мои ручные замены?**
Нет, если не была включена галочка **Also clear manual overrides**.

**Поменял стену на пол — соседние стены поменяли вид.**
Форма соседних стен изменилась (была прямая, стала угловая), поэтому им подобран вариант новой формы. Остальной уровень не трогается. Пол на месте убранной стены остаётся тем же, что был под ней.

**Между стеной и полом видна пустота.**
Значит, у клетки-стены нет пола: в наборе пола нет ни одного варианта с весом больше 0, или уровень сделан до появления слоя пола. Нажмите **Regenerate Visuals**.

**Двигаю стены рядом с дверью — дверь не меняет цвет?**
Правильно: при правке геометрии у объектов меняется только поворот, вариант остаётся.

**Ключ и дверь разного цвета.**
Скорее всего, на ключ или дверь поставлен ручной Override. Уберите его — пункт **(automatic)**.

**Что игрок видит в игре?**
Только квадрат 11×11 клеток вокруг себя (5 клеток в каждую сторону), и только то, что не загорожено стенами и **закрытыми** дверями; открытая дверь не мешает. Всё остальное — пол, стены, двери, предметы, зомби — скрыто. При планировке учитывайте: длинный прямой коридор просматривается на 5 клеток, вход в боковой проход виден заранее, а что за поворотом — нет. Сквозь щель между двумя стенами, касающимися углами, не видно.

**Нажал Play / Test from Start, ничего не произошло.**
Смотрите сообщение в окне и консоли: у уровня ошибки валидации, Unity уже в Play Mode или нет сцены Bootstrap (**Maze → Dev → Build Runtime Scenes**).
